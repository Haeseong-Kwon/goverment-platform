# 인증 메일 발송 설정 (SMTP · SPF · DKIM · DMARC)

Supabase 내장 메일은 **테스트용**입니다. 시간당 발송 한도가 낮고, 발신 주소가
`noreply@mail.app.supabase.io`라 네이버·다음 메일함에서 스팸으로 분류되기 쉽습니다.
실사용 전에 커스텀 SMTP로 바꾸고 도메인 인증(SPF·DKIM·DMARC)을 걸어야 합니다.

이 문서는 발송(outbound) 설정만 다룹니다. `hello@startuppilot.co.kr` 로 메일을 **받는** 것은
별개이며 MX 레코드가 필요합니다(현재 미설정).

---

## 0단계 — 현재 상태

2026-07-30 기준 `startuppilot.co.kr` DNS:

```
A     @      216.198.79.1                        (Vercel)
CNAME www    4f4b3c50a30fdee2.vercel-dns-017.com (Vercel)
TXT   @      (없음)     ← SPF 없음. 충돌 걱정 없이 새로 넣으면 됩니다
MX    @      (없음)     ← 수신 설정 없음
TXT   _dmarc (없음)
NS           ns.gabia.co.kr / ns1.gabia.co.kr / ns.gabia.net
```

네임서버가 가비아라 **DNS는 전부 가비아 DNS 관리툴에서** 넣습니다.

---

## 1단계 — 발송 대행사 선택

Supabase는 SMTP 서버를 제공하지 않고 **연결만** 해줍니다. 발송 대행사가 따로 필요합니다.

| | 무료 한도 | 장점 | 걸리는 점 |
|---|---|---|---|
| **Resend** (권장) | 월 3,000통 / 일 100통 | 도메인 인증이 가장 단순, 대시보드에서 발송 로그·실패 이유 확인 | DKIM을 긴 TXT로 줌 → 가비아 입력 시 주의(아래 참고) |
| **AWS SES** | 월 3,000통(12개월) | 대량 발송 시 가장 저렴, 서울 리전(ap-northeast-2), **DKIM이 CNAME 3개**라 가비아 입력이 쉬움 | 처음엔 샌드박스 상태 → 프로덕션 액세스 **신청·승인** 필요 |
| **NHN Cloud / NCP Outbound Mailer** | 소량 무료 | 국내 사업자, 원화 결제·세금계산서 | 설정 문서가 영문 대행사보다 적음 |

**추천: Resend로 시작.** 가입 당일에 끝나고, 월 3,000통은 초기 가입자 규모에 충분합니다.
발송량이 월 1만 통을 넘거나 비용이 문제가 되면 SES로 옮기면 됩니다(SMTP 정보만 교체).

> 네이버·다음 수신함 도달률이 대행사별로 어떻게 다른지는 단정하기 어렵습니다.
> 어느 쪽을 쓰든 **SPF·DKIM·DMARC를 모두 통과시키는 것**이 도달률에 가장 크게 작용합니다.

## 2단계 — 발신 주소 결정

두 가지 선택지가 있고, **루트 도메인을 권합니다.**

| | 발신 주소 | 언제 고르나 |
|---|---|---|
| **루트** (권장) | `noreply@startuppilot.co.kr` | 지금처럼 기존 메일 설정이 전혀 없을 때. 주소가 깔끔하고 신뢰도 인식이 좋습니다 |
| 서브도메인 | `noreply@mail.startuppilot.co.kr` | 마케팅 메일을 대량 발송할 계획이 있을 때. 평판이 루트와 분리돼, 문제가 생겨도 회사 메일에 영향이 없습니다 |

**루트를 골랐을 때 나중에 주의할 점:** 구글 워크스페이스 같은 걸로 회사 메일을 추가하면
SPF를 **하나의 TXT 레코드에 합쳐야** 합니다. SPF는 이름당 1개만 허용되고,
2개를 만들면 `permerror`가 되어 오히려 전부 실패합니다.

```
잘못 — TXT 레코드 2개
  v=spf1 include:_spf.resend.com ~all
  v=spf1 include:_spf.google.com ~all

올바름 — 1개에 합치기
  v=spf1 include:_spf.resend.com include:_spf.google.com ~all
```

## 3단계 — 가비아 DNS에 레코드 넣기

대행사 대시보드에서 도메인을 추가하면 넣어야 할 레코드를 정확히 알려줍니다.
**아래 값은 형태 예시**이고, 실제 값은 대행사 화면의 것을 씁니다.

가비아 → My가비아 → 서비스 관리 → 도메인 → **DNS 관리툴 → DNS 설정 → 레코드 수정**

### SPF (TXT) — 이 도메인으로 보낼 수 있는 서버 지정

| 타입 | 호스트 | 값 | TTL |
|------|--------|-----|-----|
| TXT | `@` | `v=spf1 include:_spf.resend.com ~all` | 3600 |

- `~all`(softfail)로 시작하세요. `-all`(hardfail)은 설정 실수 시 메일이 전부 반송됩니다. 안정된 뒤 바꿉니다.
- 이미 있는 TXT(사이트 소유확인용 등)는 **지우지 말고 별도 레코드로 공존**시킵니다. SPF만 1개 제한입니다.

### DKIM — 메일 본문 서명. 위조 방지의 핵심

대행사가 주는 형태에 따라 둘 중 하나입니다.

**(A) TXT 방식 (Resend 등)**

| 타입 | 호스트 | 값 |
|------|--------|-----|
| TXT | `resend._domainkey` | `p=MIGfMA0GCSq...` (매우 긴 문자열) |

⚠️ **가비아 입력 시 가장 많이 막히는 지점입니다.** 2048비트 DKIM 값은 400자를 넘어
TXT 한 조각의 255자 제한을 초과합니다.

- 가비아 입력창이 긴 값을 그대로 받아 주면 그대로 붙여넣습니다(대부분 내부적으로 쪼개 줍니다).
- 길이 오류가 나면 대행사 설정에서 **1024비트 키**로 낮추거나(대부분 지원), 아래 CNAME 방식 대행사로 바꿉니다.
- 값 앞뒤에 따옴표를 **직접 넣지 마세요.** 저장 후 조회한 값에 따옴표가 두 번 들어가면 실패합니다.

**(B) CNAME 방식 (AWS SES Easy DKIM 등) — 길이 문제가 없어 가비아에서 편합니다**

| 타입 | 호스트 | 값 |
|------|--------|-----|
| CNAME | `xxxx1._domainkey` | `xxxx1.dkim.amazonses.com.` |
| CNAME | `xxxx2._domainkey` | `xxxx2.dkim.amazonses.com.` |
| CNAME | `xxxx3._domainkey` | `xxxx3.dkim.amazonses.com.` |

### DMARC (TXT) — SPF·DKIM 실패 시 처리 방침

| 타입 | 호스트 | 값 | TTL |
|------|--------|-----|-----|
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@startuppilot.co.kr; pct=100; aspf=r; adkim=r` | 3600 |

**반드시 `p=none`으로 시작하세요.** 처음부터 `p=reject`로 두면 설정이 조금이라도 어긋난 순간
가입 인증 메일이 전부 사라집니다. 1~2주 리포트를 받아 SPF·DKIM이 안정적으로 통과하는 걸 확인한 뒤
`p=quarantine` → `p=reject`로 단계적으로 올립니다.

- `rua=` 주소로 리포트가 오므로 **받을 수 있는 주소**여야 합니다. 수신 설정(MX)이 없으면
  본인 지메일 주소를 넣어도 됩니다: `rua=mailto:본인주소@gmail.com`

### 넣은 뒤 확인

```bash
dig +short startuppilot.co.kr TXT
dig +short resend._domainkey.startuppilot.co.kr TXT
dig +short _dmarc.startuppilot.co.kr TXT
```

반영까지 10분~1시간(최대 24시간). 대행사 대시보드가 `Verified`로 바뀌면 끝입니다.

## 4단계 — Supabase에 SMTP 연결

**Authentication → Emails → SMTP Settings** → `Enable Custom SMTP` 켜기

| 항목 | 값 |
|------|-----|
| Sender email | `noreply@startuppilot.co.kr` |
| Sender name | `StartUp Pilot` |
| Host | 대행사가 준 값 (Resend: `smtp.resend.com`) |
| Port | `587` (STARTTLS 권장. 막히면 `465` SSL) |
| Username | 대행사가 준 값 (Resend: `resend`) |
| Password | 대행사 **API 키 / SMTP 비밀번호** |

⚠️ **Sender email의 도메인이 3단계에서 인증한 도메인과 같아야 합니다.**
인증 안 된 도메인으로 설정하면 대행사가 거부해 발송이 실패합니다.

### 같이 올려야 하는 것 — 발송 한도

**Authentication → Rate Limits → Rate limit for sending emails**

내장 SMTP 기준의 낮은 값이 그대로 남아 있습니다. 커스텀 SMTP를 붙였으면 대행사 한도에 맞춰
올리세요(예: 시간당 100~500). 이걸 안 올리면 SMTP를 바꿔도 **Supabase 단계에서 막혀**
"요청이 너무 잦습니다"가 그대로 나옵니다. (이 문구는 앱이 이미 한국어로 안내합니다 —
[AuthService.ts](../src/lib/services/AuthService.ts)의 `AUTH_ERROR_MESSAGES`)

## 5단계 — 실제로 보내서 검증

설정 화면의 `Verified` 표시만 믿지 말고 실제 메일 헤더를 확인합니다.

1. `/signup` 에서 **지메일 주소로** 가입
2. 받은 메일 → 우측 `⋮` → **원본 보기**
3. 상단에 아래 세 줄이 모두 `PASS`여야 합니다

```
SPF:    PASS   with IP ...
DKIM:   'PASS' with domain startuppilot.co.kr
DMARC:  'PASS'
```

- `DKIM: PASS with domain <대행사도메인>` 이면 DKIM이 **대행사 도메인으로** 서명된 것입니다.
  `startuppilot.co.kr`로 나와야 정렬(alignment)이 맞습니다. 3단계 DKIM 레코드를 다시 확인하세요.
- 네이버 메일로도 한 번 보내 보세요. 지메일보다 필터가 엄격합니다.

점수로 보고 싶으면 <https://www.mail-tester.com> 에서 생성된 주소로 비밀번호 재설정 메일을
보내면 10점 만점 진단이 나옵니다.

## 자주 나오는 실패

| 증상 | 원인 |
|------|------|
| 메일이 아예 안 옴 | Sender email 도메인이 대행사에 인증되지 않음 / Supabase 발송 한도 초과 |
| 스팸함으로 감 | DKIM 미설정 또는 도메인 정렬 불일치. SPF만으로는 부족합니다 |
| `permerror` | SPF TXT가 2개 이상. 하나로 합치세요 |
| DKIM 저장 실패 | 값이 255자 초과. 1024비트 키로 낮추거나 CNAME 방식 대행사 사용 |
| 링크가 이상한 주소로 감 | SMTP가 아니라 **Redirect URL 문제**입니다. [도메인-연결과-검색등록.md](도메인-연결과-검색등록.md) 3단계 참고 |
| 인증 메일이 예전 vercel.app 주소로 감 | Vercel의 `NEXT_PUBLIC_SITE_URL`이 아직 안 바뀜 |

## 순서 요약

```
1. Resend 가입 → 도메인 startuppilot.co.kr 추가
2. Resend가 준 SPF·DKIM 레코드를 가비아 DNS에 입력
3. DMARC는 p=none 으로 직접 추가
4. Resend 대시보드가 Verified 되면 SMTP 정보 발급
5. Supabase → SMTP Settings 에 입력 + 발송 한도 올리기
6. 지메일·네이버로 실제 가입해서 SPF/DKIM/DMARC PASS 확인
7. 1~2주 뒤 DMARC를 p=quarantine → p=reject 로 단계 상향
```
